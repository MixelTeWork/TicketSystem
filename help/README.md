# Справка

`catalog.json` задаёт разделы и статьи, `articles/<id>/text.md` содержит их текст,
а `releases/*.json` — историю обновлений. Backend выдаёт материалы с учётом прав
пользователя и кеширует их в памяти. После изменения файлов перезапустите backend.

## Как добавить статью

1. Создайте `articles/<id>/text.md`. Заголовок статьи берётся из каталога;
   не повторяйте его в тексте, подзаголовки начинайте с `##`. Поддерживается Markdown без HTML.
2. Добавьте запись в массив `articles` файла `catalog.json`, например:

   ```json
   {
     "id": "scanner-help",
     "title": "Что делать, если билет не сканируется",
     "audience": "staff",
     "section": "scanning",
     "order": 30,
     "requiredPermissions": ["scan_tickets"],
     "keywords": ["камера", "QR", "ручной ввод"]
   }
   ```

| Поле | Значение |
| --- | --- |
| `id` | Уникальный постоянный идентификатор: строчные латинские буквы, цифры и `-`, начинается с буквы, до 64 символов. Используется в папке статьи и ссылке `/help/<id>`; не меняйте его при переименовании статьи. |
| `audience` | `organizers` — для организаторов, `staff` — для сотрудников. Организаторы, Владыка и администратор видят обе аудитории. |
| `section` | `id` раздела из массива `sections`. Новый раздел добавляется туда как `{"id": "...", "title": "..."}`; разделы идут в порядке массива. |
| `order` | Порядок статей внутри раздела: меньшие значения показываются раньше. |
| `requiredPermissions` | Сотруднику нужны **все** перечисленные права. `[]` снимает только дополнительные требования к правам, но не ограничение аудитории. Организаторов этот фильтр не ограничивает. |
| `keywords` | Дополнительные слова для поиска, включая синонимы. Поиск также учитывает заголовок и текст статьи. |

Сообщения системы оформляйте `моноширинно`, названия кнопок и полей — в кавычках «…».
Для примечаний используйте `> [!NOTE]` или `> [!WARNING]`; необязательный авторский
заголовок пишется после маркера, текст — со следующей строки. Автоматического заголовка нет.

Картинки PNG, JPEG, WebP и GIF кладите в `articles/<id>/assets/` и вставляйте как
`![Описание](assets/example.png)`. Доступ к ним совпадает с доступом к статье.
